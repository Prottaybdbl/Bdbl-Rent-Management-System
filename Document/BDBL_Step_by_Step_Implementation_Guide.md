# বিডিবিএল ভাড়া ব্যবস্থাপনা সিস্টেম - ধাপে ধাপে বাস্তবায়ন গাইড

## আপনার বর্তমান অবস্থান: Planning এবং Requirement Analysis পর্যায়

এখন আপনি SDLC-এর প্রথম এবং সবচেয়ে গুরুত্বপূর্ণ পর্যায়ে আছেন। এই পর্যায়ে যা করবেন তার উপর পুরো প্রজেক্টের সফলতা নির্ভর করে।

## সপ্তাহ ১: প্রারম্ভিক পরিকল্পনা এবং স্টেকহোল্ডার ম্যানেজমেন্ট

### দিন ১-২: প্রজেক্ট কিকঅফ প্রস্তুতি

#### করণীয় কাজ:

**১. প্রজেক্ট চার্টার তৈরি (Project Charter)**

একটি ১-২ পৃষ্ঠার ডকুমেন্ট তৈরি করুন যেখানে থাকবে:

```
প্রজেক্ট নাম: বিডিবিএল ভাড়া ব্যবস্থাপনা সিস্টেম (BRMS)

উদ্দেশ্য:
- বিদ্যমান এক্সেল ভিত্তিক সিস্টেমকে স্বয়ংক্রিয় ওয়েব ভিত্তিক সিস্টেমে রূপান্তর
- ভাড়া হিসাব-নিকাশ স্বয়ংক্রিয় করা
- রিয়েল-টাইম রিপোর্টিং সুবিধা প্রদান
- বকেয়া ব্যবস্থাপনা সহজীকরণ

স্কোপ:
অন্তর্ভুক্ত:
- বিল্ডিং ব্যবস্থাপনা
- ভাড়াটিয়া ব্যবস্থাপনা
- চুক্তি ব্যবস্থাপনা
- ভাড়া এবং ইউটিলিটি বিল জেনারেশন
- পেমেন্ট ট্র্যাকিং
- রিপোর্টিং এবং ড্যাশবোর্ড

বহির্ভূত:
- একাউন্টিং সফটওয়্যার এর সাথে সরাসরি ইন্টিগ্রেশন (ভবিষ্যত ফেজ)
- মোবাইল অ্যাপ (ভবিষ্যত ফেজ)
- SMS নোটিফিকেশন (ঐচ্ছিক)

টাইমলাইন: ৪ মাস (১৬ সপ্তাহ)

বাজেট: ১২-১৫ লক্ষ টাকা (প্রাথমিক অনুমান)

প্রজেক্ট স্পন্সর: [নাম এবং পদবী]

প্রজেক্ট ম্যানেজার: [নাম]

প্রধান স্টেকহোল্ডার:
- রিয়েল এস্টেট ডিপার্টমেন্ট হেড
- আইটি ডিপার্টমেন্ট হেড
- ফিনান্স ডিপার্টমেন্ট হেড
- জিএম/সিইও
```

**২. স্টেকহোল্ডার তালিকা এবং RACI ম্যাট্রিক্স তৈরি**

| নাম | পদবী | ভূমিকা | R/A/C/I |
|-----|-------|--------|---------|
| [নাম] | রিয়েল এস্টেট হেড | প্রধান ব্যবহারকারী | A, R |
| [নাম] | আইটি হেড | টেকনিক্যাল লিড | A, R |
| [নাম] | ফিনান্স হেড | আর্থিক অনুমোদনকারী | A, C |
| [নাম] | জিএম | চূড়ান্ত অনুমোদনকারী | A |

*R = Responsible (দায়বদ্ধ), A = Accountable (জবাবদিহিমূলক), C = Consulted (পরামর্শ), I = Informed (অবহিত)*

**৩. মিটিং সিডিউল তৈরি**

প্রথম সপ্তাহের মিটিং পরিকল্পনা:
- দিন ১: প্রজেক্ট কিকঅফ মিটিং (সকল স্টেকহোল্ডার) - ২ ঘন্টা
- দিন ২: রিয়েল এস্টেট ডিপার্টমেন্ট ওয়ার্কশপ - পূর্ণ দিন
- দিন ৩: ফিনান্স ডিপার্টমেন্ট মিটিং - ২ ঘন্টা
- দিন ৪: ম্যানেজমেন্ট প্রেজেন্টেশন - ১ ঘন্টা
- দিন ৫: রিভিউ এবং ডকুমেন্টেশন

### দিন ৩: প্রজেক্ট কিকঅফ মিটিং

#### মিটিং এজেন্ডা:

1. **পরিচয় এবং প্রজেক্ট ওভারভিউ** (১৫ মিনিট)
   - প্রজেক্ট উদ্দেশ্য
   - প্রত্যাশিত ফলাফল

2. **বর্তমান সমস্যা আলোচনা** (৩০ মিনিট)
   - রিয়েল এস্টেট টিম তাদের চ্যালেঞ্জ শেয়ার করবে
   - প্রতিটি স্টেকহোল্ডার তাদের দৃষ্টিভঙ্গি দেবে

3. **প্রস্তাবিত সমাধান প্রেজেন্টেশন** (৩০ মিনিট)
   - সিস্টেমের মূল ফিচার
   - প্রস্তাবিত আর্কিটেকচার
   - স্ক্রিনশট/ওয়্যারফ্রেম (যদি থাকে)

4. **প্রজেক্ট টাইমলাইন এবং বাজেট** (১৫ মিনিট)
   - ফেজ ভিত্তিক পরিকল্পনা
   - মাইলস্টোন
   - রিসোর্স প্রয়োজনীয়তা

5. **প্রশ্ন ও উত্তর** (২০ মিনিট)

6. **পরবর্তী পদক্ষেপ এবং দায়িত্ব বন্টন** (১০ মিনিট)

#### মিটিং আউটপুট:

- [ ] সকলের থেকে প্রিন্সিপাল অনুমোদন
- [ ] প্রজেক্ট টিম গঠিত
- [ ] পরবর্তী মিটিং তারিখ নির্ধারণ

### দিন ৪: রিয়েল এস্টেট ডিপার্টমেন্ট ওয়ার্কশপ

এটি সবচেয়ে গুরুত্বপূর্ণ মিটিং। এখানে আপনি আসল প্রয়োজনীয়তা সংগ্রহ করবেন।

#### সকাল সেশন (৯:০০ - ১২:০০): বর্তমান প্রসেস ম্যাপিং

**পদ্ধতি: Process Walkthrough**

১. **ভাড়াটিয়া অনবোর্ডিং প্রসেস:**
   - প্রশ্ন: "নতুন ভাড়াটিয়া এলে প্রথম কী করেন?"
   - প্রতিটি ধাপ নোট করুন
   - কোন নথিপত্র দরকার?
   - কতক্ষণ সময় লাগে?
   - কোথায় সমস্যা হয়?

2. **চুক্তি তৈরি প্রসেস:**
   - চুক্তি তৈরিতে কী কী ধাপ?
   - কোন টেমপ্লেট ব্যবহার করেন?
   - কার অনুমোদন লাগে?

3. **মাসিক বিল তৈরি প্রসেস:**
   - কখন বিল তৈরি করেন?
   - ক্যালকুলেশন কিভাবে করেন?
   - কোথায় ভুল বেশি হয়?

4. **পেমেন্ট রিসিভিং প্রসেস:**
   - পেমেন্ট কিভাবে আসে?
   - কিভাবে রেকর্ড করেন?
   - রিসিট কিভাবে দেন?

5. **বকেয়া ম্যানেজমেন্ট:**
   - বকেয়া কিভাবে চিহ্নিত করেন?
   - ফলো-আপ কিভাবে করেন?

#### দুপুর সেশন (১:৩০ - ৪:৩০): প্রয়োজনীয়তা সংগ্রহ

**পদ্ধতি: Structured Questionnaire**

প্রশ্নাবলী ব্যবহার করে প্রতিটি মডিউলের জন্য বিস্তারিত তথ্য সংগ্রহ করুন।

**বিল্ডিং তথ্য সংগ্রহ:**
```
১. মোট বিল্ডিং সংখ্যা: _____
২. প্রতিটি বিল্ডিং এর বিস্তারিত:
   
   বিল্ডিং ১:
   - নাম: _______________
   - ঠিকানা: _______________
   - মোট ফ্লোর: _____
   - প্রতি ফ্লোরে ইউনিট: _____
   - পার্কিং স্পেস: _____
   
   [প্রতিটি বিল্ডিং এর জন্য পুনরাবৃত্তি]
```

**ভাড়া ক্যালকুলেশন নিয়ম:**
```
১. বর্গফুট ভিত্তিক ভাড়া:
   - ন্যূনতম রেট: _____
   - সর্বোচ্চ রেট: _____
   - বিল্ডিং/ফ্লোর ভিত্তিক রেট ভিন্ন? হ্যাঁ/না

২. ইউনিট ভিত্তিক ভাড়া:
   - কোন ধরনের ইউনিট? _______________
   
৩. সার্ভিস চার্জ:
   - আছে কি? হ্যাঁ/না
   - কত? _____ (টাকা বা %)
   
৪. পার্কিং চার্জ:
   - কার পার্কিং: ৳ _____
   - বাইক পার্কিং: ৳ _____
   
৫. ভ্যাট/ট্যাক্স:
   - ভ্যাট %: _____
   - ট্যাক্স %: _____
```

**ইউটিলিটি তথ্য:**
```
১. কোন কোন ইউটিলিটি ট্র্যাক করতে হবে?
   [ ] বিদ্যুৎ
   [ ] গ্যাস
   [ ] পানি
   [ ] ইন্টারনেট
   [ ] অন্যান্য: _______________

২. মিটার রিডিং:
   - কত ঘন ঘন নিতে হয়? _______________
   - কে নেয়? _______________
   - মিটার ফটো তুলতে হয়? হ্যাঁ/না

৩. বিল ক্যালকুলেশন:
   - স্লাব রেট আছে কি? হ্যাঁ/না
   - যদি হ্যাঁ, স্লাব তথ্য: _______________
```

#### ওয়ার্কশপ আউটপুট:

- [ ] সম্পূর্ণ প্রসেস ফ্লো ডায়াগ্রাম
- [ ] প্রশ্নাবলীর উত্তর
- [ ] নমুনা ডকুমেন্ট সংগ্রহ (চুক্তি, বিল, রিসিট)
- [ ] সমস্যা এবং চ্যালেঞ্জের তালিকা
- [ ] অগ্রাধিকার ভিত্তিক ফিচার তালিকা

### দিন ৫: ডকুমেন্টেশন এবং রিভিউ

ওয়ার্কশপ থেকে সংগৃহীত সকল তথ্য গুছিয়ে লিখুন। একটি প্রাথমিক FRD (Functional Requirement Document) তৈরি করুন।

## সপ্তাহ ২: বিস্তারিত প্রয়োজনীয়তা বিশ্লেষণ

### দিন ১-২: ব্যবহারকারী গল্প (User Stories) তৈরি

প্রতিটি ফিচারের জন্য ইউজার স্টোরি তৈরি করুন।

**ফরম্যাট:**
```
"একজন [ভূমিকা] হিসেবে, আমি চাই [কী করতে], যাতে [কেন/উদ্দেশ্য]"
```

**উদাহরণ:**

```
US-001: ভাড়াটিয়া যুক্ত করা
"একজন রিয়েল এস্টেট অপারেটর হিসেবে, আমি চাই সিস্টেমে নতুন ভাড়াটিয়ার তথ্য যুক্ত করতে, যাতে তাদের সকল তথ্য এক জায়গায় সংরক্ষিত থাকে।"

Acceptance Criteria (গ্রহণযোগ্যতার মানদণ্ড):
- ভাড়াটিয়ার মৌলিক তথ্য (নাম, ঠিকানা, ফোন, ইমেইল) ইনপুট করা যাবে
- একাধিক যোগাযোগ ব্যক্তি যুক্ত করা যাবে
- ট্রেড লাইসেন্স এবং টিআইএন নাম্বার সংরক্ষণ করা যাবে
- ডকুমেন্ট আপলোড করা যাবে
- ডুপ্লিকেট চেক হবে
- সফল সাবমিশনের পর confirmation message দেখাবে

Priority: High
Estimated Effort: 2 দিন
```

এভাবে প্রতিটি মূল ফিচারের জন্য ইউজার স্টোরি তৈরি করুন।

### দিন ৩-৪: ওয়্যারফ্রেম/মকআপ তৈরি

কাগজে বা ডিজিটাল টুলে (Figma, Adobe XD, বা এমনকি PowerPoint) স্ক্রিন ডিজাইন করুন।

**মূল স্ক্রিন:**

1. **লগইন পেজ**
2. **ড্যাশবোর্ড**
   - সারসংক্ষেপ কার্ড (মোট ভাড়াটিয়া, মাসিক আয়, বকেয়া)
   - চার্ট (ভাড়া ট্রেন্ড, দখল হার)
   - আসন্ন কাজ (চুক্তি মেয়াদ শেষ, পেমেন্ট ডিউ)

3. **বিল্ডিং ম্যানেজমেন্ট**
   - তালিকা ভিউ (সকল বিল্ডিং)
   - যুক্ত/সম্পাদনা ফর্ম
   - ফ্লোর এবং ইউনিট ম্যানেজমেন্ট

4. **ভাড়াটিয়া ম্যানেজমেন্ট**
   - তালিকা ভিউ
   - ফর্ম ডিজাইন
   - প্রোফাইল ভিউ

5. **চুক্তি তৈরি ফর্ম**
   - স্টেপ বাই স্টেপ ফর্ম
   - ক্যালকুলেশন প্রিভিউ

6. **বিল ম্যানেজমেন্ট**
   - বিল লিস্ট
   - বিল ডিটেইলস
   - বিল প্রিন্ট ফরম্যাট

7. **পেমেন্ট এন্ট্রি**
   - পেমেন্ট ফর্ম
   - পেমেন্ট অ্যালোকেশন

8. **রিপোর্ট পেজ**
   - ফিল্টার অপশন

## পরামর্শ: সিনিয়র ডেভেলপার হিসেবে

আপনি আইটি ডিপার্টমেন্টের একজন সফটওয়্যার ডেভেলপার। এই প্রজেক্টে আপনার ভূমিকা অত্যন্ত গুরুত্বপূর্ণ। এখানে কিছু পরামর্শ:

### ১. আত্মবিশ্বাসী হন, কিন্তু বিনয়ী থাকুন
- আপনি টেকনিক্যাল এক্সপার্ট, কিন্তু ব্যবসায়িক প্রয়োজন সম্পর্কে ব্যবহারকারীরা এক্সপার্ট

### ২. সরল ভাষায় কথা বলুন
- টেকনিক্যাল জারগন এড়ান
- উদাহরণ দিয়ে বোঝান

### ৩. প্রতিটি সিদ্ধান্তের "কেন" ব্যাখ্যা করুন
- শুধু "এটা করতে হবে" না বলে, "কেন করতে হবে" বলুন

### ৪. ধৈর্য রাখুন
- ব্যবহারকারীরা হয়তো টেকনোলজি বুঝবেন না
- একই প্রশ্ন বারবার আসতে পারে

### ৫. প্রোঅ্যাক্টিভ হন
- সমস্যা দেখলে আগে থেকে বলুন
- সমাধানও প্রস্তাব করুন
